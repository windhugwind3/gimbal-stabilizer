# SimpleFOC 到底是什么：从零开始

- 日期：2026-10-20
- 适合：刚接触无刷电机、还没搞懂 FOC 的人
- 读法：先读第 1–8 节，公式全部跳过；第 10 节是以后再看

---

## 先记住三句话

1. **无刷电机没有电刷**，要靠控制器轮流给三个线圈通电，产生一个“会转的磁场”，拉着转子转。
2. **FOC 是一种让磁场转得又平滑又准的方法**：始终让定子磁场领先转子磁场 90°。
3. **SimpleFOC 是一个现成的代码库**，帮你完成“读角度 → 算电流 → 输出 PWM”；我们用它在云台上让电机稳稳停在一个角度。

---

## 1. 无刷电机长什么样

- **转子**：上面有永磁铁，会转的部分。
- **定子**：三个线圈 A、B、C，固定不动。
- 给线圈通电，线圈产生磁场，磁场吸引/排斥转子的磁铁。
- 只给直流电：转子被吸到某个位置，不动。
- 按顺序切换线圈：转子一步一步转，这叫**六步换相**。

六步换相的问题：

- 一顿一顿，低速抖动
- 噪音大
- 效率不是最高
- 位置控制不精细

所以需要更平滑的控制方法，也就是 FOC。

---

## 2. FOC 到底在干什么

想象你在推秋千：

- 在秋千往前荡的时候推，越推越高；
- 在秋千往回荡的时候推，反而把它拽停。

电机也一样：

- 定子磁场和转子磁场**垂直（90°）**时，力矩最大；
- 两个磁场平行时，力矩为 0；
- 角度不对，就会抖、发热、没力。

有刷直流电机靠电刷和换向器，**机械地**保持这个 90°。
无刷电机没有电刷，只能靠：

1. 编码器知道转子现在在哪；
2. 算法算出三个线圈应该给多大电流；
3. 让合成磁场始终领先转子 90°。

这就是 FOC。它的结果：

- 转矩平滑
- 低速有力
- 噪音小
- 位置准
- 效率高

---

## 3. SimpleFOC 是什么，用来干什么

SimpleFOC 是一个**开源代码库**（Arduino / PlatformIO），不是一块硬件。

它帮你做这些事：

- 读编码器角度
- 做 Clarke / Park 变换
- 跑电流环、速度环、位置环
- 输出三相 PWM
- 串口调参、上位机监控

你需要做这些事：

- 接线：电机、驱动板、编码器、电源
- 配置：极对数、引脚、传感器类型
- 调参：PID
- 写上层逻辑：比如云台的目标角度

它常用在：

- 云台、稳定器
- 机器人关节、机械臂
- 无人机、电动滑板
- 转台、CNC、实验设备

一句话：**SimpleFOC 是“无刷电机控制”的现成工具箱，让你不用从零推导数学。**

---

## 4. 云台为什么需要 FOC

云台不是让电机一直转，而是：

- 让相机/平台保持水平
- 手抖、车身晃动时，快速修正角度
- 电机要低速、平滑、能“停在某个角度”

所以云台需要三层配合：

| 层 | 负责什么 | 大白话 |
|---|---|---|
| IMU | 测平台现在歪了多少 | 眼睛/平衡感 |
| 位置环 | 算出电机要转到哪 | 大脑决定目标 |
| FOC | 让电机平滑、有力地转过去 | 肌肉执行 |

没有 FOC，电机可能一顿一顿，云台就会抖；没有位置环，电机不知道要停在哪；没有 IMU，云台不知道自己是斜的。

## 5. 三个坐标系：同一个磁场箭头的三种记账方式

### 5.1 先说清楚要解决什么问题

电机里只有两样东西：

- 三个固定不动的线圈，彼此相差 120°
- 一个会转的磁铁转子

每个线圈通电都会产生磁场，三个磁场叠在一起，合成为一个**总磁场**。你可以把它想成一个箭头：有方向、有大小。

转子只对这个总箭头有反应：

- 箭头和转子磁铁垂直（90°）：力矩最大
- 箭头和转子磁铁平行：力矩为 0

所以控制器真正想控制的是：**这个箭头指哪个方向、有多大。**

但硬件只接受三个数字：三个线圈各自的电流。它听不懂“我要一个 30° 的箭头”。

所以需要一次翻译：

> 把“我要的磁场箭头”翻译成“三个线圈各给多少电流”。

FOC 做的就是这次翻译。坐标系就是翻译过程中用的记账方式。

### 5.2 坐标系到底是什么

坐标系 = **用哪几个数字来描述同一个箭头。**

举个生活里的例子。描述同一个地点：

- 甲说：往东 3 公里、往北 4 公里
- 乙说：东北方向 5 公里

地点没变，只是记法不同。

电机里也一样：同一个总磁场箭头，可以用三套数字描述。电机没有变，物理没有变，只是“账本”换了。

### 5.3 三套账本

#### abc：记三个线圈各自的电流

- 三个线圈 A、B、C，彼此相差 120°。
- 就像三个人从三个方向推一扇旋转门，abc 记的是“每个人用了多大力”。
- 三个数字，直接对应硬件。
- 缺点：三个数都在随时间变化，像三条正弦波，很难直接控制。

#### αβ：把三个力合成一个箭头

- 把三个线圈的磁场合成平面上的一个箭头。
- 用两个互相垂直的方向来描述：x 和 y（也叫 α 和 β）。
- 就像把三个人的推力合成一个总推力：方向 + 大小。
- 还是两个随时间变化的数，因为箭头在跟着转子转。

#### dq：站在转子上看同一个箭头

- 把坐标轴跟着转子一起转。
- 用两个方向描述箭头：
  - **d 轴**：沿着转子磁铁的方向
  - **q 轴**：垂直于转子磁铁的方向
- 还是同一个箭头，只是换了一个“跟着转子转的视角”。
- 好处：如果箭头始终领先转子 90°、大小不变，那么 d、q 两个数字基本不变。

| 记法 | 用几个数 | 每个数是什么 | 数字长什么样 | 适合干什么 |
|---|---|---|---|---|
| abc | 3 | 三个线圈的电流 | 三条正弦波 | 直接驱动硬件 |
| αβ | 2 | 平面箭头的 x、y | 两条正弦波 | 中间变换 |
| dq | 2 | 沿磁铁、垂直磁铁的分量 | 基本稳定的数 | PID 控制 |

### 5.4 一个具体例子

假设我们想要的总磁场箭头指向右边、长度是 1。

- 用 αβ 记：`x = 1, y = 0`
- 用 abc 记：让 A 线圈正电流，B、C 线圈负电流，具体系数取决于定义；效果是三个磁场叠加后指向右边
- 用 dq 记：如果转子磁铁也正好指向右边，那么“沿着磁铁”的分量是 1，“垂直磁铁”的分量是 0，即 `d = 1, q = 0`

如果转子转到了别的角度，同一个“指向右边”的箭头，在 dq 里的两个数字会变；但箭头本身没变。

这就是“同一个箭头，三种记账方式”。

### 5.5 为什么最后要用 dq

因为转子一直在转。

- 在 abc 或 αβ 里，箭头要跟着转子转，数字是不断变化的正弦波，PID 很难跟。
- 在 dq 里，坐标轴跟着转子一起转，箭头相对转子几乎不动，数字稳定。
- 数字稳定，普通 PID 就能控制。

所以 FOC 的流程是：

```text
编码器读出转子角度
        ↓
把目标力矩写成 dq 两个数字
        ↓
PID 算出需要的电压
        ↓
反变换回三个线圈的 PWM
```

### 5.6 `i_d = 0` 是什么意思

- **d 轴**：沿着转子磁铁的方向。往这里通电，不产生力矩，只会浪费电流、发热。
- **q 轴**：垂直于转子磁铁的方向。往这里通电，才产生力矩。

所以理想情况：

```text
i_d = 0        // 不要在“沿着磁铁”的方向浪费电流
i_q = 力矩大小  // 把电流都用在“垂直磁铁”的方向
```

用推秋千比喻：

- `i_d`：在错误的方向推，白费劲
- `i_q`：在正确的时机推，秋千越荡越高

### 5.7 一句话总结

> FOC = 用编码器知道转子在哪，把“我要的力矩”翻译成三个线圈的电流；abc、αβ、dq 只是翻译过程中的三种记账方式。

公式只是这套记账方式的数学写法，不是新的物理。现在不需要看公式；等第 9 节的调试跑通，再回来看第 10 节。

## 6. 先把这几个词串成一个故事

不要先背词。想象一个具体场景：云台上放着一台相机，你希望它始终水平。

1. 云台歪了 5°。**IMU**（姿态传感器）告诉你：“现在歪了 5°。”
2. 控制器想：“目标是 0°，现在歪 5°，要让电机往回转。”
3. 但电机不是直接听“转 5°”的命令，它需要知道转子现在在哪。**编码器**（角度传感器）负责告诉它。
4. 电机里还有三个线圈。**FOC** 根据转子角度，决定三个线圈各给多少电流，让磁场箭头领先转子 90°。
5. 电机转多少、转多快、用多大力，分别由**位置环、速度环、电流环**来管。

所以这些词不是孤立的，它们在故事里各有分工：

| 词 | 一句话 | 在故事里负责什么 |
|---|---|---|
| IMU | 测倾斜的传感器 | 知道平台歪了多少 |
| 编码器 | 测电机转子角度的传感器 | 知道电机转子在哪 |
| 极对数 | 电机一圈有几个电气周期 | 把机械角换算成电角度 |
| 电角度 | FOC 真正使用的角度 | 决定线圈该怎么换相 |
| 位置环 | 控制“停在哪” | 决定要转多少度 |
| 速度环 | 控制“转多快” | 决定用多大速度转过去 |
| 电流环 | 控制“用多大力” | 决定给线圈多少电流 |
| PWM | 快速开关控制平均电压 | 电流环最终输出的手段 |
| 闭环 | 用传感器反馈不断修正 | 让以上每一步都能自我纠正 |

先记住这个故事，再看后面的三个环和角度换算，就不会觉得它们是突然冒出来的词。

## 7. 三个控制环：老板、经理、员工

目标：让云台从歪 5° 回到 0°。

### 位置环（老板）

- 它看的是：**目标角度**和**当前角度**差多少。
- 它输出的是：**你应该以多快的速度转过去**。
- 它不直接管电流，只下命令。
- 云台是位置保持场景，所以位置环是主角。

### 速度环（经理）

- 它看的是：**目标速度**和**当前速度**差多少。
- 它输出的是：**你需要多大的力矩/电流**。
- 它的作用是防止转太快冲过头。

### 电流环（员工）

- 它看的是：**目标电流**和**实际电流**差多少。
- 它输出的是：**给线圈多大电压/PWM**。
- 它反应最快，直接执行。

把它们串起来，方向是**从外到内**：

```text
目标角度
   ↓
[位置环] → 目标速度
   ↓
[速度环] → 目标电流
   ↓
[电流环] → PWM
   ↓
电机
```

同时，编码器和 IMU 会把实际角度/速度/电流反馈回来，形成闭环。

为什么内环快、外环慢：

- 员工反应最快，老板不需要每秒改目标。
- 电流环约 10–40 kHz，速度环约 1–2 kHz，位置环约 0.5–1 kHz。
- 外环的输出是内环的输入；内环跟不上，外环再快也没用。

云台里：

- **位置环**：让平台停在目标角度，是主角。
- **速度环**：让转动不冲过头，起缓冲作用。
- **电流环**：让力矩平滑，减少抖动。

调试时不要三个环一起调。先让电机能转，再调速度环，再调位置环，最后加电流环。

## 8. 编码器、极对数、零位：角度为什么还要换算

### 编码器测的是机械角

编码器装在电机轴上，告诉你转子转了多少度，比如 0°、90°、180°。

但 FOC 需要的不是这个“机械角”，而是“电角度”。为什么？因为转子上的磁铁不止一对。

### 极对数：一圈里有几个电气周期

转子上的磁铁是一对对 N-S 排列的，不是只有一对。

- 有 7 对磁铁，就叫 **7 对极**。
- 电机机械上转一圈，磁场重复 7 次。
- 所以电气上转了 7 圈。

例子：7 对极的电机

- 机械角转 360°
- 电角度转了 7 × 360° = 2520°
- 如果控制器只按机械角算，它以为转一圈只有一个电气周期；实际有 7 个，很快就会对不上，电机抖、发热、没力。

公式：

```text
电角度 = 机械角 × 极对数 + 零位偏移
```

### 零位偏移：编码器装歪了

编码器的 0° 不一定正好对着转子磁铁的 0°。这个差值就是**零位偏移**。

不校准会怎样：

- 力矩小
- 抖动、发热
- 严重时反转或转不起来

校准思路：让电机对齐到一个已知位置，记录此时编码器的读数，把它作为零位。

### 我们的传感器

- **AS5047P**：SPI，14 位，每圈 16384 个刻度，分辨率高，适合 FOC。
- **AS5600**：I2C，12 位，每圈 4096 个刻度，地址固定 0x36。
- 两轴注意：两个 AS5600 不能挂同一条 I2C；要么用 SPI，要么分开 I2C 总线。

### 一句话总结

编码器负责“看”，极对数和零位负责“换算”，FOC 才能知道该给哪一组线圈通电。

## 9. 上手顺序（不要跳步）

1. **传感器测试**：手转电机，串口看角度是否连续、方向对不对。
2. **驱动测试**：先不接电机，测三相 PWM；接电机时电源限流 0.5 A。
3. **开环测试**：给定电压和速度，电机能平稳转。
4. **速度闭环**：编码器反馈，速度能跟上目标。
5. **位置闭环**：位置能保持，测静态误差。
6. **电流环**：采样、零漂、限幅、保护。
7. **IMU 稳定**：目标角为 0，手晃底座，平台能稳住。

每一步只改一个变量。不要一上来就同时调三个环。

## 10. 数学附录（以后再看）

### Clarke：abc → αβ

三相平衡时 `i_a + i_b + i_c = 0`：

```text
i_alpha = i_a
i_beta  = (i_a + 2 * i_b) / sqrt(3)
```

### Park：αβ → dq

```text
i_d =  i_alpha * cos(θ_e) + i_beta * sin(θ_e)
i_q = -i_alpha * sin(θ_e) + i_beta * cos(θ_e)
```

### 逆 Park：dq → αβ

```text
u_alpha = u_d * cos(θ_e) - u_q * sin(θ_e)
u_beta  = u_d * sin(θ_e) + u_q * cos(θ_e)
```

### 逆 Clarke：αβ → abc

```text
u_a = u_alpha
u_b = -0.5 * u_alpha + sqrt(3)/2 * u_beta
u_c = -0.5 * u_alpha - sqrt(3)/2 * u_beta
```

### SVPWM

把 `u_alpha/u_beta` 变成三相 PWM 占空比的方法。比正弦 PWM 的直流母线利用率更高。云台项目用 SVPWM 即可。

### 为什么 `i_d = 0`

- d 轴沿着磁铁方向，通电也不会产生力矩，只会浪费电流、发热。
- q 轴垂直于磁铁方向，产生力矩。
- 所以让 `i_d = 0`，把电流都给 `i_q`，效率最高。
